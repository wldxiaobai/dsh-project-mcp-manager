# MCP 管理页

[English](settings-ui.md) | 中文

[← 返回 README](../README.zh.md) ｜ 相关：[配置来源与分层](layers.zh.md) · [配置格式](format.zh.md) · [`${VAR}` 展开](env-expansion.zh.md) · [Lazy 设计记录](../design/lazy-mcp.md)

默认 `dsh-project-mcp-manager` bundle 内的配套包 `dsh-project-mcp-ui` 在 dsh
web 端与桌面端加一个 **MCP 管理** 页面，主页左侧栏、设置页左侧栏和设置里的插件
标签页各有一个入口：列出装载器会启动的服务器、显示每台是否在运行，并可以添加、
开关、删除服务器，选择每台服务器的加载模式，或管理单个工具。所有改动都写进
**受管 `mcp.yml`**，页面不改 JSON 文件，也不改遗留 `.mcp.json`。之后由装载器照常
经文件监听生效，所以页面和 [CLI](cli.zh.md) 可以混用。

## 安装

只需安装你所用 profile 的 **manager**：

```powershell
dsh plugin --profile web add dsh-project-mcp-manager@latest
dsh plugin --profile desktop add dsh-project-mcp-manager@latest
```

插件通过 **bundle patch** 挂载：把包加入 `dsh.profile.bundles` 后，dsh 启动时
按顺序把每个 bundle 的 patch（`dsh.bundle.patch` 指向的 `cordis.patch.yml`）合成
为插件行。

manager 以**同一精确版本**依赖 `dsh-project-mcp-ui`，会自动安装 UI。默认 bundle
包含 `mcp-project`（核心）与 `mcp-project-ui`（UI）两行，均默认启用。UI 保留
精确版本的 manager peer dependency，但不再单独声明 `dsh.bundle`，不要另选 UI
bundle。两个包必须同步发布（[版本契约](service.zh.md#对配套-ui-的语义化版本)）。
这个布局已纳入源码版本 **0.8.0**；npm 示例在两个 0.8.0 包同步发布后适用。
Git 标签不会自动发布 npm。

本地开发时，在源码仓库内执行以下命令，只链接根 manager 包：

```powershell
pnpm install
pnpm run build     # 先构建核心，再构建 UI 宿主代码与浏览器 bundle
dsh plugin --profile web add link:<源码目录>
# 桌面端改用 --profile desktop；无需另外链接 packages/ui
```

改源码后重新构建，更新链接所使用的编译产物。

headless profile 可以使用同一个 manager bundle。没有浏览器运行时就没有该页面；
缺少 dsh `connection` 服务时，UI 不注册路由，只有连接侧集成等待，
不阻塞核心装载器与 MCP 装载，UI 行本身可以独立处于 active。connection 到来时
注册对应集成，销毁时清理。

### 从单独安装的 UI 迁移

1. 先安装或升级 manager bundle。
2. 从 profile 的 bundle 选择（`dsh.profile.bundles`）中移除
   `dsh-project-mcp-ui`，保留 `dsh-project-mcp-manager`。现在由 manager 提供 UI
   行，不应继续另选旧的 UI bundle。
3. 完成第 1 步后，可以选择移除旧的**直接** UI 依赖：

   ```powershell
   dsh plugin --profile web remove dsh-project-mcp-ui
   # 桌面端换成 --profile desktop
   ```

   UI 仍通过 manager 的依赖安装。旧的直接 UI 版本可能优先于传递依赖解析：
   **运行新 bundle 之前**，建议移除旧直接依赖，或将它对齐到 manager 的精确版本。
   不要假定旧 bundle 选择或直接依赖会自动清理。

如果旧的独立 UI bundle 曾被禁用，请在**加载新 manager bundle 之前**，用下面的
profile patch 行覆盖保留停用意图：

```yaml
- id: mcp-project-ui
  disabled: true
```

只禁用旧独立 bundle 不会停用 manager 的新 UI 组件；没有这个覆盖时，默认 UI
会启用。

## 入口

入口有三个，打开的是同一个页面：

- 左侧栏的 **MCP 管理**（英文界面为 MCP Manager）。侧栏收起成 56px 轨道时
  只剩图标，悬停或键盘聚焦时显示名称；窄屏或 macOS 收起侧栏时，需要先把侧栏展开。
  这一页会取代中栏的会话视图，标题行右侧有「回到当前工作区」按钮，点它回到会话
  界面，当前会话不变。
- 设置左侧栏的 **MCP 管理**（英文界面 Settings → MCP Manager）。设置面板浮在
  会话之上，关掉就回到原来的会话位置，适合在会话进行中顺手改配置。
- **设置 → 内置插件 → 插件：MCP 管理**（英文界面 Settings → Built-in plugins →
  Plugin: MCP Manager）。旧版宿主可能把中间项显示为「插件」。

### 入口设置

在 **设置 → 通用 →「MCP 管理页入口」** 点「设置…」，弹窗里勾选主页左侧栏、
设置页左侧栏、设置页「内置插件」标签页。点「完成」一次保存，点「取消」丢弃；
另一个浏览器里的改动也会同步过来。

- 保存只写你在这个弹窗里动过的勾选项。别的窗口同时改过的设置不会被这次保存
  回滚；如果你没有改任何项，点「完成」只关闭弹窗，不写设置。
- 宿主拒绝写入（通常是另一个窗口刚保存过）时，弹窗保留你的勾选并提示。再点
  「完成」会按刚同步过来的修订重试，仍然只写你改过的项；同一项两边都改过时，
  以你这次确认的勾选为准。
- 三个入口可以全部关掉。通用里的这一行不受这三个开关影响，始终保留，用来重新
  打开入口。
- 主页左侧栏 **插件 → `dsh-project-mcp-manager`** 页面里也有同一行，两处改的是
  同一份设置。这个页面显示的 README 跟随界面语言：中文显示 `docs/README.zh.md`，
  其它语言显示根目录 `README.md`。
- 页面没有修改权限时（例如远程浏览器），勾选框禁用并给出说明。

### 隐藏整个页面

在插件管理器中展开 manager bundle 所含组件，只关闭 `mcp-project-ui`，保留
`mcp-project` 启用。也可以在 profile patch 中按 id 覆盖禁用 UI 行。这样只停用
UI（三个入口一起消失），不停用装载器，也不移除 UI 依赖。

## 当前工作区

三个入口渲染同一个面板，所以页面顶部都有同一块「当前工作区」抬头，用来回答
「我现在看的是哪个工作区」：

- 小标签「当前工作区」；
- 工作区名（路径最后一段）与完整路径同一行，路径超长时省略，悬停显示全文；
- MCP 上下文占用标签（有会话且有 MCP 工具时才出现，见下）；
- 状态行 `N 个服务器 · M 运行中 · K 待使用 · J 已禁用`，只列出非零项；
- 说明「将自动装载当前所在工作区的 MCP 服务器。」

### MCP 上下文占用

抬头里还有一个小标签 `MCP 3.4k`，表示**当前会话每次请求都要带的 MCP 工具定义**
约多少 token。它只留一个短数值，点到才展开说明：

- 估算口径是 `ceil(字符数 / 4) + 4`，与宿主的工具 schema 计价一致，不是
  provider 精确计数，也不含服务器 `instructions` 与对话历史；
- 说明气泡里给出占上下文窗口的百分比，以及定义最大的三台服务器；
- 达到 5000 时标签换成提醒色，说明里多一句「可以考虑改用懒加载」；达到 10000
  时换成警告色并加一个警告图标——数字始终显示，不只靠颜色区分，标签的
  `aria-label` 也会读出阈值。

还没有会话、或当前会话里没有 MCP 工具时，这个标签不出现。数字变化时会自动刷新：
宿主在请求头或路由信息变化后重发一次更新信号，页面据此重读。

宿主还确定不了焦点时（多个工作区且还没有会话焦点），名称显示「当前工作区未确定」，
隐藏路径，说明改为「打开一个会话或发送一条消息后确定。」。抬头里的计数只算这个
工作区的行，用户层与 profile 层的服务器不计入；启动中、失败等其它状态不单列，
但仍计入总数。active Lazy 行计入**待使用**，不计入运行中。这是展示层的投影：按需
行可能已经有一个打开的代理连接；卡片和抬头都不投影连接状态，所以「待使用」不等于
「没有连接」。

工作区分组也按焦点排：当前工作区那一组置顶，标题后挂「当前」标签；其它分组不挂标签。

## 列表里显示什么

服务器按分节显示：

| 分节 | 文件 |
|---|---|
| 工作区层 | 各已知项目的 `<projectRoot>/.dsh/mcp.yml`、`.dsh/mcp.json`、`.mcp.json` |
| profile 层：桌面端 / web 端 / `<name>` 端 | `~/.dsh/profiles/<当前 profile>/mcp.yml` 与 `mcp.json` |
| 用户层 | `~/.dsh/mcp.yml`、`~/.dsh/mcp.json` |

用户层与 profile 层路径用 `~` 表示家目录，工作区路径保持原样。

**装载器会启动的每台服务器一张卡。** 合并规则与装载器的影子规则一致（精确名、
归一名、服务身份，见[配置来源与分层](layers.zh.md)）：

- 低优先级文件里的同名行留在胜出者卡片上，说明「已被覆盖」。
- 名字不同、但命令与参数相同（或地址相同）的行：来自 yml 时在胜出者卡片上
  说明；来自 JSON 时不显示，因为装载器不会启动它。

名字旁的标签是来源文件。黄色的「`<文件>` · 待接管」表示这一行来自 JSON 文件或
`.mcp.json`，改动前会先确认（见下文）。

**状态行**：

| 状态 | 含义 |
|---|---|
| 运行中 · N 个工具 | 已连接，工具已注册。开关为绿色。 |
| 可按需连接 | 已启用的按需加载行。按需连接不投影到卡片，可能已经由上次调用打开；下一次 `mcp_search` / `mcp_describe` / `mcp_call` 直接使用，已关闭则重新连接。 |
| 已启用 · 等待装载 | 已打开但未装载，例如宿主尚未装载该配置。开关为白色。 |
| 正在启动 | 正在装载。页面会持续刷新，直到有结果。 |
| 启动失败 | 连接失败。 |
| 未启动 · 名称已被占用 / 缺少环境变量 / 环境变量展开后无效 / 配置无效 / 已停止重试 | 装载器跳过了这一行，下一行写完整原因。 |
| 已禁用 | 这一行已关闭（`disabled: true`）。 |

每次对账后页面会自动刷新（SSE 推送，断开时退回轮询），所以在编辑器或 CLI 里
改的配置也会显示出来。

## 添加服务器

点「添加 MCP」：

1. **保存到**：工作区（当前工作区的 `.dsh/mcp.yml`）、用户（`~/.dsh/mcp.yml`）
   或 profile（`~/.dsh/profiles/<当前>/mcp.yml`）。下方显示将写入的路径。还没有
   在某个工作区打开会话时「工作区」不可选；解析不出当前 profile 时「profile」
   不可选。
2. **名称**：1–32 位字母、数字、`_` 或 `-`。该文件里已有同名时拒绝，文件不动。
3. **加载模式**：直接加载（缺省）或按需加载；见[加载模式](#加载模式)。
4. **类型**：本地命令（stdio）或远程地址（Streamable HTTP）。
5. 本地命令：命令、参数（每行一个）、环境变量（每行一个 `KEY=值`）。远程地址：
   地址、请求头（每行一个 `名称: 值`）。`${VAR}` 原样写入，装载时展开
   （[`${VAR}` 展开](env-expansion.zh.md)）。

「添加」写入一条受管行并发起对账。工作区里的 stdio 行写 `cwd: .`（项目根），
用户层与 profile 层继承宿主目录。

**从剪贴板填入**读取剪贴板里的 JSON 或 YAML 并填表。认 `mcpServers` 或
`servers` 映射、单个条目，以及受管 yml 行。有多个服务器时只填第一个，并说明
其余几个没有填入。`enabled: false` 的条目跳过；SSE（`type: "sse"`）条目会被
拒绝，因为装载器装不了。浏览器可能会请求剪贴板权限。保存位置保持对话框里当前
的选择。

表单不覆盖 `tools.allow`/`deny` 模式、`reconnect`、超时和 `maxInstructionBytes`，
这些请用「MCP 配置」。

## 加载模式

每张服务器卡片都有「加载模式」控件：**直接加载**（缺省）或**按需加载**；添加对话框
里也有同一个控件。选择写进受管 yml 的 `config.mode`；缺省即直接加载，显式写
`config.mode: eager` 等价。

- **直接加载**保留原有行为：挂载时连接，每个工具注册进 DSH。需要服务器 instructions、
  DSH Resources、按单个注册工具名配置的宿主策略，或「管理工具」逐项开关时用它。
- **按需加载**在每个会话首次 `mcp_search` 时单独连接。不带 `server` 的搜索会连接
  所有可见的按需服务器，可能同时启动多个进程。已激活的连接保留到会话结束或配置
  卸载、替换。按需行显示「可按需连接」，「管理工具」按钮隐藏。
  页面不会主动探测按需服务器，连接失败要到第一次搜索或调用时才暴露。需要逐项开关时，
  改该行来源文件里的 `tools.allow`/`deny`，或切回直接加载。
- 切换模式只写受管 yml，不会把停用行启用：停用行切换后仍然是停用。目标行没有
  有效连接配置时（例如手写的、只有 id 的 disabled 占位），切换会被拒绝，文件不动。
  JSON 文件或 `.mcp.json` 来源的行不会被改写：页面先确认，再在同一作用域的受管 yml
  写一条更高优先级的覆盖行，原文件不动；写入位置仍受「当前工作区 / 用户层 / 当前
  profile」限制。
- 按需加载不是安全边界：stdio 命令仍会在第一次使用时启动；`mcp_call` 可以调用任何
  通过该行 `tools.allow`/`deny` 且对当前会话可见的工具。按 `mcp__<服务器>__<工具>`
  注册名配置的宿主策略看不到按需工具；需要这种策略时用直接加载。
- 两种模式的完整差异（连接时机、instructions/Resources、`reconnect`、
  `maxInstructionBytes`、超时）见[配置格式](format.zh.md#加载模式)与
  [Lazy 设计记录](../design/lazy-mcp.md)。

## MCP 配置

「添加 MCP」旁的菜单用系统默认编辑器打开一份受管 `mcp.yml`：用户层文件、当前
profile 文件，以及每个已知工作区各一份。文件不存在时先创建 YAML 空列表（`[]`），
第一次写服务器时再生成受管块。
Windows 上会同时在资源管理器里选中它。写法见[配置格式](format.zh.md)。

## 开关、删除与工具

- **开关**：受管 yml 行就地翻转 `disabled`。
- **删除**：先确认。受管 yml 行直接删掉；如果更低优先级的文件里还有同名或
  同命令的行，改为保留一条 `disabled: true` 占位，避免那一条再启动。
- **管理工具**：列出运行中服务器已注册的工具，每个一个开关。切换会把精确工具名
  写进该行的 `tools.allow` / `tools.deny`。未运行的服务器没有工具可列；按需加载行
  不显示这个按钮（见[加载模式](#加载模式)）。

**来自 JSON 文件或 `.mcp.json` 的行**不会被就地修改。每次改动都先弹确认，再在
同一作用域的受管 yml 里写一条更高优先级的行，原文件不变：

| 卡片来源 | 写入 |
|---|---|
| `.dsh/mcp.json`、`.mcp.json` | 该工作区的 `.dsh/mcp.yml` |
| profile `mcp.json` | profile `mcp.yml` |
| `~/.dsh/mcp.json` | `~/.dsh/mcp.yml` |

启用会拷贝整条配置；停用或删除写一条占名的 `disabled: true` 占位（`disabled`
如何遮蔽低层见[配置来源与分层](layers.zh.md)）。切换加载模式同样写覆盖行，并保留
停用状态。

**工作区层卡片只能改当前工作区的。** 其它工作区的卡片置灰（「这个工作区当前
不能改」）。用户层与 profile 层卡片始终可改。

## 安全

在页面上添加本地命令服务器，等同手写一条 `stdio` 行：dsh 宿主会 spawn 这个
命令。按需加载只是延后连接，不是延后信任：第一次搜索或调用仍会启动 stdio 命令；
不带 `server` 的搜索会连接当前会话所有可见的按需服务器。页面路由
（`/api/project-mcp/*`）挂在 dsh connection 上，能使用这个 dsh
web GUI 的人就能通过它添加并启动服务器。GUI 的访问权限应当等同受管配置文件的
写权限来对待。

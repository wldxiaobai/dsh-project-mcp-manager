## 用户可见变化

- **左侧栏新增「MCP 管理」**。点开是同一个服务器列表页，整页宽度比设置弹窗宽；
  侧栏收起成 56px 轨道时只显示图标，悬停或键盘聚焦显示名称。图标为数据库形状，
  位置紧跟「插件」。
- **两个入口并存一个版本**。新页面顶部写明旧设置页会保留到下一个版本；旧设置页
  顶部写明新入口的位置，并说明本页将在下一个版本移除。
- **隐藏方式不变**。只关闭 manager bundle 所含的 `mcp-project-ui`（或 profile
  patch 按 id 覆盖禁用）就同时隐藏左侧栏与设置页两个入口，装载器继续运行。

## 宿主对齐：dsh 0.2.1-rc.5

- `@deepseek-ai/dsh-mcp-client`、UI 的 `@deepseek-ai/dsh-native-command`、client
  开发依赖，以及两包 `engines.dsh` 一起抬到 `^0.2.1-rc.5`。
- 为什么是「抬下限」而不是「保持 rc.2」：rc.5 client 的 peer 是精确版本的 rc.5
  包，npm 会把 `^0.2.1-rc.2` 解析成 rc.5；在 rc.2–rc.4 宿主上会装出一套对不上的
  peer。声明 rc.5 为下限，旧宿主会得到明确的引擎拒绝，而不是静默混装。
- 已逐项核对 rc.5 的运行时接口：client 的 `Config` schema、导出、传输集合、
  reconnect 上限与 MCP SDK 2.2.0 均未变；`sidebar.panellist`、`main`、
  `settings.plugins.tab` 仍由 rc.5 的对应包声明；`connection.fetch.register`
  的入参形状不变；页面用到的 primitives 图标仍在 web 前端模块表里。
- `pnpm-workspace.yaml` 的 `minimumReleaseAgeExclude` 从 rc.2 换成 rc.5，避免
  供应链年龄策略把新版本过滤掉、回落到旧 tuple。

## 迁移提示

- 升级到 0.10.0 后无需改配置、无需迁移文件；两个入口读写的仍是同一批受管
  `mcp.yml`。
- 如果你还在 dsh 0.2.1-rc.2–rc.4，请留在插件 v0.9.0；升级宿主到 rc.5 后再装
  0.10.0。
- 0.11.0 会移除设置标签页。如果你的操作手册或内部文档写着
  「设置 → 内置插件 → 插件：MCP 管理」，现在就可以改成左侧栏「MCP 管理」。

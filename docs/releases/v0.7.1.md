## 变更明细

- **后台入队（审查 S1 / Sonar S9383）**：构造函数的 `agent/created`、`agent/disposed`
  与插件热更补扫三处，加上文件事件 `kick`、宽限卸载 timer、`kickSweep`，全部改走新的
  `schedule()`——`enqueue()` 的返回值不再被丢弃，失败会记一条
  `项目 MCP 后台任务失败：<原因>`。此前这类失败被链路完全吞掉：对账没跑成，日志里
  什么也看不到。诊断落盘（fiber settle 后的 `active` / `failed`）仍走独立的
  `enqueueDiag()`：同样排回对账链，但按最佳努力静默失败。
- **死代码（审查 B1）**：删掉 `DEFAULT_MAX_INSTRUCTION_BYTES`。「缺省不写键、让官方
  默认值生效」的口径由字段注释与四处输出（官方配置 / 受管行 / view / JSON 条目）的
  测试固定，不需要再在本地留一份 32768。
- **回归测试（审查 B2、B3）**：新增两条用例——
  `agent/created` 带 `source: "resume"` 时补扫并挂载会话项目，且对被自己项目行遮蔽的
  全局实例应用 deny（项目侧压制展开成精确工具名）；`planProjectChanges` 在
  `maxInstructionBytes` 这类连接字段变化时产出 unmount → mount，而 `tools` 变化不拆连接。
- **小重构（审查 S7503、S9381、S9382）**：`enqueue()` 签名放宽为 `() => T | Promise<T>`，
  `serverView()` / `snapshot()` 去掉只为满足签名的 `async`；`trackMount` 的 fiber settle
  回调改调 `enqueueDiag()`，消掉嵌套 Promise；配置指纹的逐文件 `stat` 改 `Promise.all`
  并发发起（签名仍按排序后的路径逐条拼接，结果与串行一致）。

## 用户可见变化

- **只剩一个入口**。0.10.0 里并存一个版本的「设置 → 内置插件 → 插件：MCP 管理」
  标签页已删除，左侧栏的 **MCP 管理** 行是唯一入口。页面顶部原来的迁移提示也一并
  去掉。
- **隐藏方式不变**。只关闭 manager bundle 所含的 `mcp-project-ui`（或 profile
  patch 按 id 覆盖禁用）就隐藏左侧栏入口，装载器继续运行。
- **升级后无需迁移配置**。两个版本读写的仍是同一批受管 `mcp.yml`。

## 宿主对齐：dsh 0.2.2-rc.1

0.2.2 系列首个候选版把工具链整体换代：cordis 4.1.0、loader 1.1.0、
include 1.1.0、timer 1.2.0、schemastery 3.19.0，最低 Node 提到 24.9。逐项核对
之后，本插件用到的接口都没有形状变化：

- **mcp-client 逐字节兼容**：`Config` 判别联合、reconnect 上限、MCP SDK 2.2.0、
  导出列表与 0.2.1-rc.5 相同，装载器代码无需改动。
- **工具面**：`tools.restrict()` 多了「必须来自 agent 作用域」「不得点名 `run_code`」
  两条前置校验——本插件本来就是 `agent.ctx.tools.restrict({ deny })`，deny 里只有
  `mcp__*` 工具名。`tools.schemas()` 只是把签名扩成可选的两个参数，无参调用行为不变。
- **工具执行器拆分不影响本插件**：发布说明里要求迁移的 `tools.resolve/executable`
  与提示词组装接口，针对的是**直接注册工具**的插件；本插件经 mcp-client 装载，
  不自己注册工具。
- **会话与连接**：`agent/created` 仍是 `{ agent, source, signal? }`，
  `session.header.cwd` 仍是会话原始项目，`connection.fetch.register` 的入参形状未变。
- **cordis 4.1.0**：`ctx.effect(execute, label)` 与 `ctx.plugin(plugin, config)` 仍在。
  loader 1.1.0 的 entry 只暴露 `options.config`、没有顶层 `config` 访问器；
  `globalNames()` 与 `activeProfile()` 本来就写成 `entry?.config?.X ?? entry?.options?.config?.X`，
  这条回退正好接住，所以没有改动。

依赖下限抬到 `^0.2.2-rc.1` 而不是继续写 rc.5，理由和上一版相同：rc.1 client 的
peer 是精确版本的 rc.1 包，`^0.2.1-rc.5` 会被解析成 rc.1，在旧宿主上混装出一套
对不上的 peer。声明 rc.1 为下限，旧宿主会得到明确的引擎拒绝。
`pnpm-workspace.yaml` 的 `minimumReleaseAgeExclude` 同步换成 rc.1 与 cordis 4.1.0，
避免供应链年龄策略把新版本过滤掉、回落到旧 tuple。

## 安装与升级

```powershell
# 新装（桌面端把 --profile 换成 desktop）
dsh plugin --profile web add dsh-project-mcp-manager@0.11.0

# 从 0.10.0 升级：重跑同一条 add，带上目标版本
dsh plugin --profile web add dsh-project-mcp-manager@latest
```

UI 由 manager 以同一精确版本自动安装，不需要单独安装或选择 `dsh-project-mcp-ui`。
升级宿主到 dsh 0.2.2-rc.1 之前不要装 0.11.0。

---

## 迁移提示

- 如果你的操作手册或内部文档还写着「设置 → 内置插件 → 插件：MCP 管理」，现在
  必须改成左侧栏「MCP 管理」——旧路径已经不存在。
- 还在 dsh 0.2.1-rc.2–rc.5 的部署请留在插件 v0.10.0：v0.11.0 的 `engines.dsh`
  会拒绝旧宿主。

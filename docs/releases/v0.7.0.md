**发布日期**：2026-09-30 ｜ **区间**：`v0.6.0 → v0.7.0`
**宿主**：dsh `0.2.0` 线，从 `0.2.0-rc.2` 起。dsh 0.1.5 继续使用插件 v0.6.0。

官方 dsh 仍不发现项目级 MCP 文件、不按会话 cwd 隔离工具、也没有 MCP 专用 CLI。
v0.7.0 把装载后端对齐到宿主自带的 `@deepseek-ai/dsh-mcp-client@0.2.0-rc.2`，
并补上这一版新增的配置字段。

---

## 亮点速览

| 主题 | 一句话 |
|---|---|
| 依赖下限 | `@deepseek-ai/dsh-mcp-client` 抬到 `^0.2.0-rc.2`；cordis 开发依赖 `^4.0.4` |
| 会话事件 | 删除已不存在的 `agent/session-start`；补扫由 `agent/created`（含 `source`）承担 |
| instructions 上限 | 可选透传 `maxInstructionBytes`；缺省不写键，官方默认 32768 |
| 定位 | 承认官方 profile patch / HMR / resources；本插件留下项目发现、会话隔离、CLI |

---

## 用户可见变化

- 支持矩阵改为 **dsh ≥ 0.2.0-rc.2**（`0.2.0` 元组）。`^0.1.5-rc.1` 解析不到
  `0.2.0-rc.*`，不改范围就会在新宿主里嵌一套旧 client。
- `.dsh/mcp.yml` 与 JSON 方言可以写 `maxInstructionBytes`（整数 ≥ 1）。省略时
  不把 32768 抄进配置。超限由官方 client 拒绝该次连接。`dsh-mcp` 不增加对应参数。
- 官方 stdio 会丢掉父进程里名字像凭据的环境变量和 `DSH_*`。写进 `env` 并经
  `${VAR}` 展开的值仍然传给子进程。

## 为什么回退

0.11.0 把两个入口合并成一个，理由是“同一个页面不需要两扇门”。实际使用里两者
**不是同一个位置**，差别足以影响可达性：

| | 设置标签页 | 左侧栏面板 |
|---|---|---|
| 呈现 | 浮在会话之上 | 取代中栏，会话视图切走 |
| 关掉后 | 回到原会话原位置 | 要重新点回会话 |
| 侧栏收起时 | 不受影响 | 56px 轨道只剩图标 |
| 窄屏（< 1024px） | 不受影响 | 侧栏变抽屉，要先展开 |
| macOS 收起侧栏 | 不受影响 | 整列隐藏 |

也就是说：侧栏收起、窄屏、macOS 收起这三种情况下，0.11.0 之后页面**只剩一个
需要先展开侧栏才能到达的入口**；而既有文档、团队 runbook 里写的大多是设置路径。
恢复第二个入口比要求用户改习惯更划算。

---

## 用户可见变化

- **两个入口都回来了**，打开的是同一个页面。左侧栏 **MCP 管理** 行、**设置 →
  内置插件 → 插件：MCP 管理**（旧版宿主可能把中间项显示为「插件」）。
- **没有任何迁移提示**。0.10.0 里那种“旧入口保留一个版本、下版移除”的说明不会
  再出现——这两个入口是长期方案。
- **隐藏方式不变**。只关闭 manager bundle 所含的 `mcp-project-ui`（或 profile
  patch 按 id 覆盖禁用）就同时隐藏两个入口，装载器继续运行。
- **两个入口各自开一条 SSE**。它们不共享状态，但在任一处写入后都会收到
  `projectMcp/updated` 并自行刷新，所以两边看到的内容一致。

## 技术细节

- 恢复 `settings.plugins.tab` 注册（`id: projectMcp`、`order: 30`），直接注册
  `McpPanel`，不再额外包一层外壳。
- `dsh.client.inject` 回到六项，重新包含 `@deepseek-ai/dsh-client-ui-settings` 与
  `@deepseek-ai/dsh-client-ui-settings-plugins`——`slots.inject` 需要槽位包先加载，
  否则注册会一直等待。
- 删除 `entryNoticeNew` / `entryNoticeOld` 两条文案与 `McpSettingsTab` 外壳、`.dsh-mcp-notice` 样式；保留 `tab` 与 `panelLabel`。
- `@deepseek-ai/dsh-client-ui-settings` 与 `@deepseek-ai/dsh-client-ui-settings-plugins`
  回到 client devDependencies（`0.2.2-rc.1`）与 esbuild externals。
- 版本按补丁号走：这是对 0.11.0 引入的可达性退化的修复，不新增行为。

## 安装与升级

```powershell
# 从 0.11.0 升级（桌面端把 --profile 换成 desktop）
dsh plugin --profile web add dsh-project-mcp-manager@latest
```

UI 由 manager 以同一精确版本自动安装。仍需要 dsh ≥ 0.2.2-rc.1；0.2.1-rc.2–rc.5
请继续用 v0.10.0。

## 变更

### `@deepseek-ai/dsh-mcp-client` `^0.1.2-rc.1` → `^0.1.5-rc.1`

`^0.1.2-rc.1` **不会**解析到 `0.1.5-rc.1`：npm semver 要求带 prerelease 的
候选版本与比较符的 major.minor.patch 元组相同。v0.4.2 因此在 dsh 0.1.5-rc.1
宿主进程里加载插件自带的 0.1.2-rc.1 客户端及其 0.1.2-rc.1 peer
（`dsh-tools` / `dsh-scope` / `dsh-timeout` 等）。

升到 `^0.1.5-rc.1` 后，mcp-client 与全部 peer 解析到 **0.1.5-rc.1**，与宿主
同版。pnpm 12 为这批刚发布的 rc 写入 `pnpm-workspace.yaml` 的
`minimumReleaseAgeExclude`，否则供应链门禁会挡住安装。

静态核对：`tools.restrict`、`agents.list` / `isOwnedBy`、会话事件名、
mcp-client `Config`、`serverName` 约束、`mcp__<name>__<tool>` 命名与
`MAX_TIMER_DELAY_MS` 均无断裂。实现 diff 仅 `tools/list` 增加重复
continuation cursor 校验。

隔离实机：`ProjectMcpRegistry` 读项目 `.dsh/mcp.yml` 后
`scan` → `attempt` → `active`，`mcp__compat-probe__probe` →
`pong:compat-015`。完整记录见
[适配记录](../design/adaptation-dsh-0.1.5-rc1.md)。

## 升级

无破坏性变更，无需改任何配置文件。

已装 v0.4.2 且宿主已升到 dsh 0.1.5-rc.1 的 profile，把插件升到 v0.4.3
即可去掉进程内双副本：

```powershell
dsh plugin --profile <p> add dsh-project-mcp-manager@0.4.3
```

本地 link 开发：`pnpm install` 后确认
`@deepseek-ai/dsh-mcp-client` 解析为 `0.1.5-rc.1`。

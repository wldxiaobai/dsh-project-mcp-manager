## 亮点速览

| 主题 | 一句话 |
|---|---|
| Lazy 加载模式 | 每行可选 `mode: lazy`，工具不预先注册，经 `mcp_search` / `mcp_describe` / `mcp_call` 按需发现和调用（[#30](https://github.com/wldxiaobai/dsh-project-mcp-manager/pull/30)） |
| 常驻挂载 | 已发现的工作区在插件运行期间保持装载，切换会话不再卸载或重连；按会话 deny 隔离（[#32](https://github.com/wldxiaobai/dsh-project-mcp-manager/pull/32)） |
| 首条请求可见 | 新建会话在 `agent/created` 返回前最多等 20 秒，让首条模型请求就能看到 Eager 工具（#32） |
| 隔离兜底 | 新会话首次 `tools.restrict` 失败时 fail-closed，临时 deny 全部 MCP 工具并自动重试（#32） |
| 上下文占用 | 抬头新增 `MCP {定义}` 与 `结果 {调用结果}` 两个估算标签，超过 5,000 / 10,000 token 时提醒（[#33](https://github.com/wldxiaobai/dsh-project-mcp-manager/pull/33)） |
| 工程 | 测试套件按领域拆分（[#34](https://github.com/wldxiaobai/dsh-project-mcp-manager/pull/34)），新增中英双版贡献指南 |

## 为什么做

- **工具定义太占上下文。** 一个工具多的 MCP 服务器装上后，每次请求都要带上它的
  全部 schema。不常用的服务器改成 Lazy，只在模型搜索时连接，定义不进常驻工具表。
- **按需挂载会反复断连。** v0.12.0 在工作区最后一个会话结束 5 分钟后卸载它的
  服务器，回到该工作区时要重新连接，期间工具不可见；有状态的服务器也会丢上下文。
  改为常驻挂载后，切换会话只改变可见性，不触碰连接。
- **新会话首条请求看不到工具。** 宿主在 `agent/pre-step` 之前就冻结本步工具快照，
  旧实现在那里等待没有效果。等待移到 `agent/created` 后，首条请求即可见。
- **用户不知道 MCP 占了多少上下文。** 抬头标签直接给出估算数和占上下文窗口的比例，
  不用再自己数工具。

## 用户可见变化

### Lazy 加载模式

每行可写 `mode: eager`（缺省）或 `mode: lazy`。原生 `mcp.yml` 写在行的 `config` 里，
JSON 方言写在条目顶层，`dsh-mcp import` 会保留它；CLI 没有 `--mode` 参数。

```yaml
    - id: panel-mcp-gitlab
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: gitlab
        mode: lazy
        transport: stdio
        command: npx
```

- 有启用的 Lazy 行时，宿主注册三个代理 `mcp_search` / `mcp_describe` / `mcp_call`；
  看不到任何 Lazy 行的会话会 deny 这三个名字，只用 Eager 的会话不多出工具。
- 每个会话首次 `mcp_search` 时为目标服务器建立自己的连接；同一会话的搜索、描述、
  调用共享连接，跨空闲与工作区切换保持，会话结束、行卸载或插件退出时释放。
  未搜索就 `mcp_describe` / `mcp_call` 会提示先搜索。
- 行级 `tools.allow` / `tools.deny` 对 Lazy 同样生效，完整工具名与 Eager 用同一套
  64 字符规范化与哈希口径。
- Lazy 不读 instructions 和 Resources，不执行 `reconnect` / `failOnStartupError`，
  `maxInstructionBytes` 不生效；连接与列工具用固定 30 秒发现超时。需要这些能力时
  继续用 Eager。完整对照见[配置格式：加载模式](../guide/format.zh.md#加载模式)。
- MCP 管理页的服务器卡片和「添加 MCP」对话框都有 Eager / Lazy 选择，写入受管
  mcp.yml 的 `config.mode`。active 的 Lazy 行在抬头计为「待使用」，卡片显示
  「可按需连接」，不显示「管理工具」。

### 工作区常驻挂载

- 已发现且有 MCP 配置的工作区在插件运行期间保持装载。切换会话或某个工作区的
  会话全部结束，都不再卸载它的服务器。每个会话只看到自己工作区与全局层的工具、
  instructions 和 Resources，靠按会话 `tools.restrict({ deny })` 隔离。
- 焦点只决定管理页显示哪个工作区、写入哪个受管文件。
- 新发现的工作区与已挂载的 Eager 重名时，只给新行改名（`p<hash>_<原名>`），在线
  连接不重挂。
- 管理页去掉了旧的「空闲」标签与说明；已启用但还没装载完的行显示「已启用 · 等待装载」。

### 新会话与隔离

- 新建会话在 `agent/created` 串行返回时先落 deny，再等它可见的 Eager 服务器就绪，
  上限 20 秒、每 100 毫秒检查一次。启动时恢复的会话不等待。
- 新会话第一次 `tools.restrict` 失败、又没有上一份限制时，改为 fail-closed：临时
  deny 全部已注册的 `mcp__` 工具，而不是让它看见所有工作区的工具。兜底期间该会话
  的系统提示词带一段 MCP 保护通知（成因简述与恢复办法，不含原始错误文本），并在
  对账链外按 500 毫秒 / 2 秒 / 5 秒退避重试，对账卡住也能恢复；事件记入全局诊断
  `restrict-fallback`。

### MCP 上下文占用

工作区抬头多了两个标签，数字始终可见，颜色不是唯一信号，标签带 `aria-label`：

- `MCP 3.4k`：会话实际暴露的 MCP 工具定义（经 `tools.restrict` 与行级过滤之后），
  按 `dsh-token-meter` 的 `ceil(字符数 / 4) + 4` 口径估算。低于 5,000 为中性色，
  5,000 起提醒色，10,000 起警告色加图标。三个 Lazy 代理只算一组「Lazy 代理（共享）」，
  不按服务器重复计；计算时不会发起发现或连接。
- `结果 1.2k`：会话当前上下文里仍保留的 MCP 工具调用结果。Eager 结果按服务器归属，
  Lazy 结果按 `mcp_call` / `mcp_describe` / 指定 `server` 的 `mcp_search` 参数归属，
  不指定服务器的搜索归入共享代理组。已被裁剪或压缩掉的结果不计。
- 点开标签的气泡给出估算依据、占上下文窗口的比例、占用最多的服务器，结果气泡另给
  定义与结果的合计。没有会话或没有 MCP 工具时标签隐藏。
- 数字跟随宿主当前选中的会话，其次是最近一次顶层用户回合所在的会话；子代理回合
  与压缩替换不会抢走它。
- 代码模式（PTC，请求工具表里有保留的 `run_code`）下两项合并为中性的
  「MCP 无法估算」，因为定义被渲染进系统提示词、调用嵌在 `run_code` 里，这套口径
  算不出来。切回原生执行器后恢复估算。

这些数字是估算，不是 provider 的计数，也不含服务器 instructions。

## 技术细节

- **查询面**（`projectMcp`，均为新增）：`setLoadingMode(source, projectRoot, rawName, mode)` 只改
  受管 yml 的 `config.mode`，不等待对账；`contextCost(sessionId?)` 与
  `resultCost(sessionId?)` 只读估算，代码模式返回 `unsupported: "code-mode"` 且数值
  字段归零。行视图与新增草稿多了可选 `mode`。占用签名变化时（`request/header`、
  `request/context`、`tool/result`、压缩替换、同工作区活动会话切换之后）再 emit 一次
  `projectMcp/updated`，页面不轮询。详见[查询面](../guide/service.zh.md)。
- **包入口新增导出**：类型 `McpLoadingMode`、`ContextCostLevel`、`McpContextCost`、
  `McpServerContextCost`、`McpResultCost`、`McpResultServerCost`；函数与常量
  `mcpContextCost`、`mcpResultCost`、`mcpServerOfTool`、`contextCostLevel`、
  `contextCostSignature`、`resultCostSignature`、`estimateSchemaTokens`、
  `estimateMessageTokens`、`estimateContentTokens`、`isCodeModeTools`、
  `CODE_MODE_TOOL_NAME`、`CONTEXT_COST_WARN_TOKENS`（5000）、
  `CONTEXT_COST_ALERT_TOKENS`（10000）。
- **UI 状态路由**：`/api/project-mcp/state` 增加 `contextCost` / `resultCost`，
  服务器行带 `mode`；`/api/project-mcp/server` 新增 `action: "mode"`，
  `/api/project-mcp/add` 接受 `mode`。
- **新增运行时依赖**：Lazy 路径直接使用 `@modelcontextprotocol/client@2.2.0` 与
  `@deepseek-ai/dsh-subprocess@0.2.2-rc.1`（清理父进程环境后 spawn），均为精确版本，
  与官方 `dsh-mcp-client` 的声明对拍；升级须通过兼容性与官方命名对拍测试。取舍见
  [Lazy 架构与依赖决策](../design/lazy-mcp.md)。
- **移除**：按需挂载与「最后一个会话结束 5 分钟后卸载」的宽限（内部
  `UNMOUNT_GRACE_MS` 与 `unmountGraceMs` 注入项，二者都不在包入口导出）。诊断不再
  产生 `idle` 跳过原因和 `summary.idle`；含这些字段的旧诊断文件仍可解析，
  `dsh-mcp status` 仍能读出。
- **测试套件重组**：`test-registry.mjs` 拆成
  `test-registry-{pure,layers,core,service,lazy,context}.mjs`，共用假宿主放进
  `test/helpers/registry-harness.mjs`；`test-bundle.mjs` 与 `test-lazy-dependencies.mjs`
  合并为 `test-package-contract.mjs`；`test-ui-paste.mjs` 更名 `test-ui-add-server.mjs`，
  `packages/ui/test/panel-helpers.mjs` 并入根测试。UI 包里指向已删文件的 `test` 脚本
  同步删除，测试统一从根目录 `pnpm test` 运行。
- **贡献指南**：新增 [CONTRIBUTING.zh.md](../../CONTRIBUTING.zh.md) 与英文版，两版
  README 末尾链接。

## 兼容性与安装

```bash
# 从 0.12.x 升级（桌面端把 --profile 换成 desktop）
dsh plugin --profile web add dsh-project-mcp-manager@latest
```

UI 由 manager 以同一精确版本自动安装。仍需要 dsh ≥ 0.2.2-rc.1；0.2.1-rc.2–rc.5
请继续用 v0.10.0。

没有迁移步骤：

- 不写 `mode` 的行仍是 Eager，现有 `mcp.yml` / `mcp.json` / `.mcp.json` 不用改。
- 已有服务方法、CLI 命令与诊断文件格式保持兼容，新增字段都是可选的。
- 行为差异：工作区不再在最后一个会话结束后卸载，后台常驻的 stdio 进程会比
  v0.12.0 多。不想常驻的服务器可以改成 Lazy，或在管理页禁用。
- 依赖 v0.12.0 内部 `unmountGraceMs` 注入项的外部测试需要删掉该项。

## 本次不做

- CLI `--mode` 参数（改文件或用管理页切换）。
- Lazy 的 instructions、Resources、`reconnect` 与 `failOnStartupError`。
- 上下文占用计入服务器 instructions，或改用 provider 的真实计数。
- 代码模式（PTC）下的占用估算。
- 按空闲时长自动卸载工作区。

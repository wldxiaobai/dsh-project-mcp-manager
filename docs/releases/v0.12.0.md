## 为什么做

v0.11.1 只有两个 UI 入口，而且只能整体停用 `mcp-project-ui`。实际使用里有三件
事需要解决：

1. **入口可控**：有的部署只想要设置里的入口，有的只想保留主页图标行，但之前只能
   全开或全关。
2. **位置补齐**：不想用主页图标行的用户，在设置里也应该能找到页面；「设置 →
   内置插件」这一层在有些宿主里藏得比较深。
3. **不迷路**：插件按当前工作区自动挂载/卸载服务器。主页页面取代了中栏会话，
   必须有一条明确的返回路径；用户也需要一眼看到「现在这个页面属于哪个工作区」。

不改装载器、查询面、CLI、配置格式与文件写入，也不做跨入口状态共享。

## 用户可见变化

### 三个入口

| 入口 | 位置 | 外壳 |
|---|---|---|
| 主页左侧栏 | `sidebar.panellist` + `main`（同一 id `project-mcp`） | 标题行 + 返回按钮 + `McpPanel` |
| 设置页左侧栏（新） | `settings.section` + `settings.section.icon`（同一 id） | 设置外壳自己的标题与关闭按钮；内容只有 `McpPanel` |
| 设置页「内置插件」标签页 | `settings.plugins.tab`（id `projectMcp`） | 无，直接 `McpPanel` |

三个入口渲染同一个面板，各自一条 SSE，不做跨入口状态共享。

### 入口显隐

设置 → 通用 新增一行 **MCP 管理页入口**（`settings.general.item`，id
`mcp-entries`、order 12）：标题 + 说明 + 右侧「设置…」按钮。点开的小窗里有三个
勾选框：主页左侧栏、设置页左侧栏、设置页「内置插件」标签页。

同一行也注册到 `plugins.bundle.config`（key 为 bundle 包名
`dsh-project-mcp-manager`），出现在主页左侧栏 **插件 →
`dsh-project-mcp-manager`** 页面里；插件管理器据此把该 bundle 当作有配置项。两处
写的是同一份表单，任一处保存后另一处立即同步。

- 弹窗里是草稿：打开时从表单快照初始化，点「完成」把有变化的字段合成一次
  `mutate` 提交，然后关闭；「取消」丢弃草稿。
- 三个入口可以全部关掉；通用里的这一行不属于这三个开关，始终保留，是恢复入口。
- 值落宿主设置文档里 `mcp-project-ui` 这一条，不写 profile patch；浏览器经
  `ctx.configForms.get("mcp-project-ui")` 读写，另一个浏览器的改动也会同步。
- 页面没有写入权限（远程浏览器）时，三个勾选框禁用并显示说明；写入失败时保留
  弹窗并显示错误文案。
- 关闭主页入口时，如果正停在该页，先 `selectPanel(null)` 回到会话，再一起释放
  `main` 与侧栏行；关闭设置分区时成对释放导航行与图标。

### 当前工作区抬头

三个入口的面板顶部都有同一块抬头，自上而下：

1. 小标签「当前工作区」；
2. 工作区名（路径最后一段）与完整路径同一行（代码字体，路径超长时省略，悬停看全文）；
3. 状态行 `N 个服务器 · M 运行中 · K 待会话 · J 已禁用`，只显示非零项；
4. 说明「将自动装载当前所在工作区的 MCP 服务器。」

没有焦点时显示「当前工作区未确定」，隐藏路径，说明改为「打开一个会话或发送一条
消息后确定。」。计数只算这个工作区的行；启动中、失败等其它状态不单列，但计入
总数。用户层与 profile 层的行不计入抬头。

工作区分组同步这个焦点：当前工作区那一组置顶并挂「当前」标签；其它仍有行在等
会话的组挂「空闲」，并附一句「切到该工作区时装载。」。已有更具体跳过原因的行
不会让该组多出「空闲」。

### 返回按钮

只在主页侧栏页的标题行出现：图标 + 「回到当前工作区」，行为是
`ctx.layout.selectPanel(null)`——回到会话界面，**不改变当前会话**。它不拦截 Esc、
不锁焦点、不画遮罩，只是一条导航。设置分区与插件标签页没有这个按钮，设置外壳
自己的关闭按钮就是它们的退路。

## 技术细节

- 宿主半区 `McpUiState` 增加 `activeProject: string | null`，取
  `projectMcp.writeTargets()` 里 `id === "project"` 的 `projectRoot`。这与「添加
  MCP」默认写入位置同源，所以不需要改 `projectMcp` 服务契约，也不需要新增方法。
- `packages/ui/src/index.ts` 导出 `Config`（schemastery）：
  `sidebar` / `settingsSection` / `settingsTab` 三个布尔，默认 `true`，都标
  `.volatile()`——宿主只把 volatile 字段投影进设置表单（`settings.volatileForm`），
  不标的话 `mcp-project-ui` 这个命名空间不会出现在 `describe()` 里，页面读不到也
  改不了。`packages/ui` 因此新增 `@deepseek-ai/schemastery@~3.19.0` 依赖。
- 浏览器半区 `inject` 从 `["slots", "locale"]` 扩到
  `["slots", "locale", "layout", "configForms"]`。DSH Web 与桌面端默认组合始终
  提供这两个服务；设置域缺席时整个客户端插件不激活，与缺少槽位包时一致。
- 入口开关行注册两次：`settings.general.item`（id `mcp-entries`）之外，还注册
  `plugins.bundle.config`（keyed slot，key 为 `dsh-project-mcp-manager`），由插件
  管理器渲染在该 bundle 的详情页。两处共用同一个 `ConfigForm` 和提交函数；行组件
  用 `variant="page"` 去掉通用行的分隔线与内边距。
- 槽位描述集中在 `packages/ui/src/client/entries-registry.ts`；显隐配置模型与
  提交操作在 `entries-settings.ts`；幂等增删注册在 `entries-controller.ts`；
  通用行组件在 `entries-row.tsx`；抬头与分组判断（纯函数）在 `workspace.ts`。
- 没有新增全局壳层（状态栏、底部栏），没有改 `main` 的 keyed 语义，也没有把面板
  状态提成共享 store。

## 安装与升级

```powershell
# 从 0.11.x 升级（桌面端把 --profile 换成 desktop）
dsh plugin --profile web add dsh-project-mcp-manager@latest
```

UI 由 manager 以同一精确版本自动安装。仍需要 dsh ≥ 0.2.2-rc.1；0.2.1-rc.2–rc.5
请继续用 v0.10.0。

没有迁移步骤：

- 三个入口默认全显示，v0.11.1 的行为不变。
- 新设置项只写在宿主设置文档里，不要求改 `cordis.patch.yml` 或 profile patch。
- 仍可在插件管理器里只关闭 `mcp-project-ui` 整体停用 UI；装载器 `mcp-project`
  不受影响。

## 本次不做

- 卡片式主页（`main` 选中即卸载会话，卡片背后不会是会话）。
- 会话头部 MCP 计数、工作区树标记、切换 toast。
- 全局壳层（状态栏 / 底部栏）、右侧栏新标签页、动态侧栏 label。
- 跨入口共享面板状态或 SSE。
